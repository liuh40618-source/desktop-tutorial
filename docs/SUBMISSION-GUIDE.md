# 新致杯参赛提交指引

> 公开仓库已清理个人联系方式。正式提交前，请仅在本地填写队长姓名、电话和邮箱。
> 依据：主办方《第二届"新致杯"人工智能创新大赛参赛通知》（邮件原文）。
> 本指引只转述通知已写明的内容；通知未规定的，一律标注为「未规定」，不替主办方补充规则。
> 在线版本见 [`/submit`](../app/submit/page.tsx)。

---

## 一、提交入口

**唯一入口：邮件附件。**

| 项 | 内容 |
| --- | --- |
| 收件邮箱 | `marketing@newtouch.com` |
| 提交方式 | 将全部参赛文件打包为 zip，作为邮件附件发送 |
| 邮件主题 | 与压缩包同名（不含 `.zip`） |
| 压缩包文件名 | `项目名称 + 队长姓名.zip` |
| 截止时间 | **2026 年 10 月 23 日 24:00**，逾期未提交视为自动弃赛 |

通知未提供在线提交表单、提交系统或提交查询入口。**没有第二种提交方式。**

### 关于文件名中的加号

通知原文写作「项目名称 + 队长姓名.zip」。本项目默认按**字面加号**生成，即 `职途+[队长姓名].zip`
（队长姓名取自 `submission/submission.config.json`）。
若主办方核对时不认加号，把 `submission/submission.config.json` 中的
`packaging.separator` 改为空字符串 `""`，即可生成 `职途[队长姓名].zip`。

## 二、所需字段与格式

全部字段写在 `submission/submission.config.json`，打包脚本据此生成提交包与包内《提交信息》。

| 字段 | 配置路径 | 格式 | 要求 |
| --- | --- | --- | --- |
| 项目名称 | `project.name` | 文本 | **必填**，决定压缩包文件名 |
| 队长姓名 | `project.captain.name` | 文本 | **必填**，决定压缩包文件名 |
| 队长联系电话 | `project.captain.phone` | 文本 | **必填**，官方人员将电话沟通项目进展 |
| 队长邮箱 | `project.captain.email` | 邮箱 | 建议填写，便于接收沟通 |
| 队员名单 | `project.members` | 字符串数组 | 选填，含队长每队不超过 5 人 |
| 指导教师 | `project.advisor` | 文本 | 选填，学生队伍可额外配备 1 名 |
| 所属行业领域 | `project.industry` | 文本 | 建议填写，通知列举金融 / 医疗 / 汽车 / 教育 / 法律等 |
| 材料类型 | `materials.docType` | `产品说明书` \| `商业计划书` | **必填**，二选一 |
| Demo 形式 | `materials.demoType` | `视频` \| `网站` \| `其他` | **必填** |
| Demo 地址 | `materials.demoUrl` | URL | 仅当 Demo 形式为「网站」时填写 |
| AI 工具及用途 | `aiCoding.tools[]` | `{name, usage}` 列表 | **必填**，名称与用途成对提供 |

## 三、与提交相关的文档清单及具体要求

### 3.1 必须随包提交的文档

| 文档 | 数量 | 具体要求 | 存放位置 |
| --- | --- | --- | --- |
| **产品说明书** 或 **商业计划书** | 恰好 1 份 | 二选一。内容须包含下列五项：<br>① 产品介绍<br>② 设计思路<br>③ 设计过程<br>④ 商业价值与/或产品创新性说明<br>⑤ AI Coding 工具使用情况 | `submission/materials/doc-*` |
| **产品 Demo** | 至少 1 个 | 通知原文为「视频、网站或其他形式均可」，未限定扩展名 | `submission/materials/demo-*` |

> 通知写明：**两项均须提交，材料不完整视为弃赛。**

提纲模板见 `submission/templates/`：
- [`01-产品说明书-提纲.md`](../submission/templates/01-产品说明书-提纲.md)
- [`02-商业计划书-提纲.md`](../submission/templates/02-商业计划书-提纲.md)

### 3.2 由脚本自动生成的文档

| 文档 | 生成方式 | 作用 |
| --- | --- | --- |
| `00-请先打开我.html` | 打包时自动写入 zip 根目录 | 材料入口页：内嵌 Demo 直达链接、推荐体验路径、包内清单、AI 工具表。评审双击即可进入产品，不必先读文档 |
| `01-提交信息.md` | 打包时自动写入 zip 根目录 | 列明项目、队长、成员与 **AI Coding 工具名称及具体用途**，直接满足通知的披露要求 |
| `源码/` | 打包时自动收进 zip | 完整产品源码（约 126 个文件），作为 Demo 的离线凭证；可 `npm install && npm run dev` 复现同一产品 |
| `dist/submission/SUBMISSION-REPORT.md` | 打包时生成，不进 zip | 校验结果、提交指引、可复制的邮件正文 |

### 3.3 作为说明书素材来源的项目内文档

产品说明书第 ⑤ 项「AI Coding 工具使用情况」有现成素材，不必从零写：

| 项目文档 | 可支撑说明书中的哪一部分 |
| --- | --- |
| [`docs/AI_LOG.md`](AI_LOG.md) | ⑤ AI Coding 工具使用情况（工具名、用途、人机分工） |
| [`docs/NEWTOUCH.md`](NEWTOUCH.md) | ① 产品介绍、④ 创新性说明 |
| [`docs/COMPETITION-ITERATION.md`](COMPETITION-ITERATION.md) | ② 设计思路、③ 设计过程 |
| [`README.md`](../README.md) | ① 产品介绍、算法与数据边界 |
| `docs/USER-VALIDATION.md` | ④ 商业价值中的用户验证证据（当前为待执行方案） |

> 注意：`docs/AI_LOG.md` 开头自述为"回顾性记录"且声明统计数字"不应作为量化结果提交"。
> 赛制把 AI Coding 过程列为核心考察点，提交前应把该文档重构为**可核验的过程记录**
> （带时间戳的交互、提交记录、人机决策对照），而不是回顾性叙述。

## 四、关键约束

### 4.1 主办方明示

| 约束 | 内容 |
| --- | --- |
| 截止时间 | 2026 年 10 月 23 日 24:00，逾期视为自动弃赛 |
| 打包格式 | zip |
| 命名规范 | `项目名称+队长姓名.zip`，邮件主题同名 |
| 材料完整性 | 说明书/计划书 与 Demo 两项均须提交 |
| 文件类型 | Demo「视频、网站或其他形式均可」，未限定扩展名 |
| AI 工具披露 | 须注明 AI 工具名称及其具体用途 |
| 队伍限制 | 每人仅参加一个项目、一支队伍；每队不超过 5 人 |
| 脱敏要求 | 涉密内容须在参赛前脱敏处理 |

### 4.2 主办方未规定

- 附件大小上限（通知未给出任何数值）
- 说明书 / 计划书的页数或字数
- 材料语言（中文或英文均未限定）
- Demo 视频时长

**不要把工程惯例当成赛事规则写进材料。**

### 4.3 工程建议（非主办方约束）

| 建议 | 理由 |
| --- | --- |
| 提交包总量 ≤ 25MB | 主流邮箱单附件上限约 25MB，超出易被退信。超出时改用网盘链接并在正文说明 |
| 说明书导出为 PDF | 避免评审端字体缺失导致错版 |
| Demo 视频用 MP4（H.264）、1080p | 兼容性最好；码率过高会迅速撑爆附件上限 |
| **随包附源码**（`源码/`） | Demo 为在线网站，源码是唯一的离线凭证：链接失效时评审仍可本地复现；同时支撑「AI Coding 工具使用」的披露。当前全包约 1.9MB，远低于 25MB |
| 仍不放进 `node_modules/`、`.next/`、`career.db*`、日志 | 体积巨大且与参赛材料无关；打包脚本已自动排除，并跳过 2MB 以上的单文件 |
| 提前 2–3 天发送 | 留出退信重发的时间窗口 |

## 五、提交后的确认方式

通知**未提供**自动回执或提交查询入口。可按以下顺序自行确认：

1. 发送后立即保留邮件「已发送」截图与附件列表截图，作为按时提交的凭证。
2. 保持队长电话畅通——通知写明官方人员将在比赛期间电话沟通项目进展。
3. 队长按通知要求扫码添加官方人员、加入官方赛事交流群，在群内确认材料是否收到。
4. 若 24 小时内未获任何回应，再次邮件询问并在群内同步。

> 本项目不代发邮件，也无法代替主办方确认收件。最终是否被接收以主办方回复为准。

## 六、操作步骤

```bash
# 1. 填写提交元数据（队长姓名、电话、AI 工具用途为必填）
#    编辑 submission/submission.config.json

# 2. 放入材料（文件名分别以 doc- 与 demo- 开头）
#    submission/materials/doc-职途产品说明书.pdf
#    submission/materials/demo-职途演示视频.mp4

# 3. 先校验，再打包
npm run submit:check     # 只校验，不产出 zip；有阻断项时退出码为 1
npm run submit:build     # 校验通过后产出提交包
```

### 产出物

| 路径 | 用途 |
| --- | --- |
| `dist/submission/职途+[队长姓名].zip` | 直接作为邮件附件发送（名称由配置推导） |
| `dist/submission/SUBMISSION-REPORT.md` | 校验结果、提交指引、可复制的邮件正文 |

校验存在阻断项时，脚本以非零退出码结束且**不产出 zip**，避免误发材料不完整的包。

## 七、常见失败原因

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 脚本报「未找到产品说明书」 | `materials/` 里没有 `doc-` 前缀文件 | 按约定重命名或补放材料 |
| 脚本报「找到 2 份说明书」 | 同时放了说明书和商业计划书 | 通知要求二选一，只保留 1 份 |
| 脚本报「缺少 usage 用途说明」 | 只填了 AI 工具名 | 补 `usage` 字段，名称与用途成对 |
| 脚本报「队长电话为空」 | 未填联系电话 | 补齐；官方将电话沟通 |
| 邮件被退信 | 附件超出邮箱上限 | 改用网盘链接，或压缩 Demo 码率 |
| 主办方核对文件名不通过 | 加号非字面要求 | 把 `packaging.separator` 改为 `""` |
