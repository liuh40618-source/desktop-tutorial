# 职途参赛迭代说明与下一阶段验收

日期：2026-09-23。
赛事口径按参赛者提供的通知统一为：第二届“新致杯”人工智能创新大赛，预选赛作品截止 10 月 23 日 24:00。当前文档依据该通知整理，不推断通知未提供的赛道或评分规则。

本地参赛说明页为 `/competition`，从 `/plan` 页脚进入。该页说明教育场景、目标痛点、AI Coding 工具及用途，并列出提交核对项。

## 产品定位与本轮纠偏

职途是面向大学生的职业试选工具。用户首先需要解决“我做过的事能用在哪，接下来值得试什么”，而不是管理一组求职指标。上一轮的工作台、侧栏和指标首页没有服务好这个问题，本轮已替换。

主流程：写经历 → 核对候选能力 → 比较不同方向 → 检查证据缺口 → 先做一件具体作品。界面以「看见经历、比较选择、动手验证」三个章节组织，岗位库与记录为辅助入口。

不是招聘平台，不做录用概率预测，不把关键词识别包装为大模型推理。当前行动仍是技能练习，尚不能宣称是经行业验证的职业模拟或已经验证有效的职业决策干预。

## 本轮实现

- 首页直接写一段课程、社团、项目或实习经历，专业与年级选填；空白不能提交，可进入手动核对能力。
- 原话中的关键词与候选能力对应展示，随后由用户确认；撤去未经评测的“置信度”颜色暗示。
- 候选方向不直接展示分数前三名。从有技能交集的模板中，按现有排序选出「沿用已有能力」、其他意向中最靠前的「回应你的意向」（若存在）、未选方向中的「换个方向看看」。至多三项，不重复方向、不用零交集岗位凑数。
- 方向详情并列呈现已有起点与缺口。分段图每格代表一项要求，区分自评有项目、待补作品、待补技能；不表示权重。
- 计算公式与证据边界可展开查看。分数仍为规则匹配分，不是兴趣测评结果或录用概率。
- 行动页突出当前一项交付物、验收标准、时间与资源。完成后保留勾选反馈，由用户主动查看下一项；完整清单与完成记录折叠保留。
- 增加独立的「职业试驾」入口：不要求先写经历或确认技能，可做数据分析、前端交互、产品分析三项约 15 分钟的工作样本，提交后查看自查清单与参考思路。
- 试驾记录答案、卡点复盘和继续意愿，形成按体验方向回看的个人档案，并可导出 Markdown；不自动打职业分、不把反馈当作能力或作品核验。
- 新增行动后的作品复盘：记录作品 / 材料名称与位置、个人贡献、过程体验及继续意愿；按用户自评提供“开始下一项行动 / 再试一项 / 比较其他方向”的直达操作。复盘随草稿保存，并进入规划 Markdown 导出；不上传作品文件，也不把自评当作外部核验。
- 真实 JD 不再止于收藏与覆盖率卡片：保存前可删除误命中技能、补充漏识别技能；可将确认过的 JD 作为目标进入同一套差距检查和行动计划，并回看原文。原文没有给出的技能权重、硬门槛和薪资不做推断。
- 真实 JD 的跨岗位矩阵改用岗位 ID 关联技能，避免重名岗位串列；删除需得到服务端成功响应，失败时保留原卡片并提示。
- 去掉上一轮未再使用的 Dashboard 组件、工作台样式和外部办公照片依赖。
- 示例不自动覆盖个人草稿，退出后恢复经历；用户主动保存示例规划仍会新增记录。

## 保留的可靠性改进

- 匹配等待知识库初始化，方向均值使用库内全部岗位，不再只用 Top20。
- 技能覆盖和项目证据覆盖分开计算。项目证据仅指已确认技能且用户自评等级 >= 3，未经外部验证。
- 去掉没有真实市场采样依据的稀缺度加分，分数拆解与计算一致。
- 补技能与补作品进入同一行动队列，优先级先按核心权重、再按权重/估算时长排序。
- 交付物、验收与自查状态进入导出的 Markdown；完成行动不自动提升技能或证据等级。
- 保存规划等待持久化结果；两种存储都不可用时显示失败，不虚报成功。
- 草稿恢复优先浏览器缓存；规划合并本地兜底与服务端记录，同 ID 以本地为准。保存成功清理本地对应兜底，删除失败保留原记录并提示。
- 个人草稿、规划和 JD 已改为按 HttpOnly 签名访客会话分区，服务端忽略客户端传入的用户 ID，读写与删除均限制在当前会话；无需注册，但换浏览器或设备不自动同步。
- 知识库观察的技能比例从岗位引用量计算，不再称市场稀缺度。修正薪资档位分桶。
- 升级 Next.js 及相关依赖，移除构建期 Google 字体下载依赖。

## 当前边界

- 主入口是 `/plan`；根路径 `/` 已补 307 重定向到 `/plan`，两个地址都可用。主流程不再挂在根路径。
- 无账号访客模式依赖浏览器中的 HttpOnly 会话 Cookie；没有跨设备找回。SQLite 仍按单实例方式运行，正式公网部署还需配置后台口令并验证部署环境、容量和滥用防护。
- 简历上传到应用服务端解析；本机运行时留在本机进程，远程运行时会到远程服务器。不能笼统承诺“永不上传”。
- 证据等级是自评，不检查附件或第三方证明。
- 579 岗位、134 技能、17 方向为人工模板，不是实时职位，也没有完整逐条采样记录。
- 经历关键词识别仍可能误命中，人工确认不能被省略。
- 学习资源是平台搜索入口，不是已经审核的指定课程。
- 没有真实大模型调用。若赛道要求产品使用大模型，需按官方规则另行接入并评测；AI 辅助开发不等同于 AI 产品能力。

## 下一阶段验证

本轮直接迭代本地工程，未建立云端副本、未公开部署。以下为后续待办，不代表已经实现。

1. 先验证产品假设：邀请目标学生完成一次试选，记录卡点、理解偏差、候选选择理由与行动开始情况，不只收集“界面好看”的反馈。
2. 邀请有相关经验者校验三项职业试驾任务的情境、输入材料、交付物和参考思路，再观察目标学生是否能独立完成并从体验中得到有用信息。
3. 将现有行动复盘汇总到「我的记录」，支持跨规划回看；继续把“愿意继续 / 不确定 / 暂停”作为自我记录，不自动判定职业适合度。
4. 把复盘材料沉淀为可复用的技能证据条目，支持标题、描述、可选链接和本人贡献；没有人工审核不能称“已核验”。
5. 已统一 JD 与经历关键词边界识别，避免 Java/JavaScript、SQL/NoSQL 的嵌入误命中；否定、学习中和经验有限等邻近表述会提示人工核对。规则仅作提醒，仍需用真实经历和 JD 样本评估误报、漏报与上下文范围。
6. 若增加模型，默认关闭，未配置时规则模式完整可用；明确数据发送提示、超时降级与结构化输出校验，并开展规则/模型对照评测。
7. 若公开多人体验，核实生产环境是否启用 Secure Cookie、为管理后台配置 `ADMIN_TOKEN`，并在目标部署上验证 Nginx 速率限制、SQLite 单实例运行和个人数据清除流程。

## 3 分钟演示顺序

1. 打开 `/plan`，点「试一段示例」，从一段具体经历进入，不先讲指标与功能数量。
2. 点「拆开这段经历」，展示原话、用户确认能力与自评证据的区别。
3. 展示少量不同方向，切换候选，解释“为什么值得试”及“哪里仍有缺口”。
4. 展开选择依据，说明分数怎么算以及它不能证明什么。
5. 选一个方向，检查证据后进入当前行动，展示具体交付物与验收标准。
6. 完成一项，停留查看完成反馈，保存并进入记录；退出示例证明个人草稿没有被覆盖。
7. 有余时再演示真实 JD 对照，强调模板不等于某家企业的要求。
