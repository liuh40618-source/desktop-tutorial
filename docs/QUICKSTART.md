# 快速上手 · 3 分钟

## 1. 安装

```bash
npm install
```

> 需要 Node.js >= 22.5.0（用了内置 `node:sqlite`）

## 2. 启动

```bash
npm run dev
```

浏览器打开 **<http://localhost:4000>**（根路径 307 跳转到 `/plan`，两个地址都能用）

> 首次启动会自动从 `data/*.json` 构建 SQLite 数据库（`career.db`），约 1 秒。

## 3. 走完三个章节

界面按「看见经历 → 比较选择 → 动手验证」组织，不再是早期的五步向导。

| 章节 | 做什么 | 预计耗时 |
| --- | --- | --- |
| 01 看见经历 | 写一段做过的课程 / 社团 / 项目 / 实习经历，核对原话中的关键词与候选能力，确认后自评证据等级 | 30 秒 |
| 02 比较选择 | 从有技能交集的模板中给出至多 3 个不同方向，比较已有起点与缺口，选定一个目标岗位 | 30 秒 |
| 03 动手验证 | 先呈现一项含交付物与验收标准的行动，完成后主动切下一项，可保存、回看与导出 Markdown | 20 秒 |

方向候选至多三项、不重复方向、不用零交集岗位凑数；候选来自现有规则排序，不是兴趣测评结果。

**懒人路径**：`/plan` 首页点「试一段示例」→「拆开这段经历」，全程约 60 秒。
示例不会覆盖个人草稿，点「返回我的经历」即恢复原草稿。

**真实 JD 对照**：顶部「岗位库」→ 粘贴 JD 原文（含岗位职责与任职要求）→ 点「识别 JD 技能」→
检查命中技能与别名证据 → 点「确认识别结果并保存」→ 查看 JD 覆盖率、缺口技能与估算学习时间。
完整示例文本见 [`LOCAL_DEMO.md`](LOCAL_DEMO.md)。

## 常见问题

**Q: 页面打不开？**
先确认 `npm run dev` 还在跑——终端窗口关掉，服务就一起停了。重启后访问 <http://localhost:4000>，
根路径会自动跳到 `/plan`。

**Q: 端口 4000 被占了？**
改 `package.json` 里 `dev` 脚本的 `-p 4000` 为其他端口。

**Q: 数据库报错 / 数据不对？**
删掉 `career.db`（及 `.db-shm`、`.db-wal`），重启 `npm run dev` 会自动重建。

**Q: 想改岗位 / 技能数据？**
编辑 `data/jobs.json` 或 `data/skills.json`，然后跑：
```bash
node scripts/data/validate-data.mjs
```
校验通过后，删掉 `career.db` 重启即可生效。也可以用 `/admin` 后台改（直接写库）。

**Q: 简历导入支持什么格式？**
PDF / DOCX / TXT / MD，<= 5MB。在应用服务端进程内解析（unpdf / mammoth），不落盘、不调用外部接口。
如果部署在远程机器上，文件会到达那台服务器，不能笼统承诺「永不上传」。

**Q: 需要联网吗？需要 API Key 吗？**
不需要。全程零 LLM、零外部 API，匹配与识别都在本地算完，没有需要配置的模型密钥。
唯一的环境变量是后台口令 `ADMIN_TOKEN`（见 `.env.example`，本地开发可留空）。

**Q: 后台要不要设置口令？**
本机开发可不设；局域网或公网暴露必须设置较长随机口令，否则任何人都能改数据。
