# 职途首轮用户试用脚本

> 用途：发现流程理解、任务内容和信任表达的问题。小样本试用只能提供定性线索，不能证明产品提升了职业决策或就业结果。

## 参与者与时长

- 首轮建议邀请 5–8 名在校学生，覆盖不同年级或专业；另请至少 2 名相关从业者审阅职业试驾任务。
- 每位学生约 25–35 分钟。测试前说明这是产品测试，不是能力测评；可以跳过问题或随时结束。
- 不要求提供真实简历。鼓励使用虚构 / 脱敏经历；不收集姓名、电话、学校学号、雇主机密等信息。
- 录音或录像需另行征得同意。记录使用 P01、P02 等匿名编号，不保存原始简历或包含身份信息的截图。

## 主持原则

先让参与者自己操作，不先解释算法或替他们选方向。卡住时先问“你现在想做什么”，再给最少提示，并记录提示内容。把“没看懂”和“不同意系统建议”分开记录。

## 学生任务

1. **写一段经历**：请参与者用一次课程、社团、项目或实习经历开始；不愿分享时可选“试一段示例”。观察字段是否帮助他们说清个人贡献和结果。
2. **核对能力**：请参与者查看候选能力，确认至少一项并拒绝或移除一项（若候选允许）。询问哪句原话支撑判断，哪些候选不准确。
3. **比较方向**：请参与者切换候选方向并选一个愿意继续了解的方向。询问他们依据的是兴趣、已有能力、缺口，还是分数；观察“匹配分”是否被误解为适合度或录用概率。
4. **选一项行动**：请参与者查看差距和行动计划，说出本周实际会做的第一步，以及还缺什么资源或信息。
5. **可选：职业试驾**：参与者选择一项工作样本，尝试完成并对照参考思路；记录任务是否读得懂、材料是否够用、时间是否接近标示值，以及参与者是否愿意继续类似任务。

## 从业者任务审阅

请审阅者逐项检查三项工作样本的情境是否可信、输入材料是否充分、交付物是否能被检查、初学者能否在标示时间内完成、参考思路是否允许多种合理解法。记录需要补充的专业背景、可能误导新手的假设和估时偏差；不要把审阅意见写成行业共识。

每次结束后再记：最有帮助的一处、最不可信或最困惑的一处、参与者离开产品后打算做什么。不要把“愿意继续”直接当成职业适配结论。

## 结束提问

- 哪一步最容易理解，哪一步最难？
- 有没有哪项技能或方向明显不符合你的经历？为什么？
- 你认为页面上的分数说明了什么？它不能说明什么？
- 你会把哪项行动带到现实中去做？还有什么阻碍？
- 如果只能改一处，你希望改什么？

## 汇总方式

首轮结束后汇总任务完成率、需要提示的步骤、重复出现的误解、技能误命中类型、参与者能否说明下一步，以及从业者指出的任务问题。样本量较小，只报告“本轮参与者中观察到的情况”；不推断总体用户比例，也不宣称提升了就业或职业决策结果。若同一问题在多位参与者中重复出现，先修复再做下一轮。
