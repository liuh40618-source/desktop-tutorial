## 一、产品介绍

### 1.1 一句话定位

> 从我说我会，到我能展示——把职业目标拆成可解释、可执行、可验收的成长行动。

### 1.2 目标用户

面向教育场景中的大学生与应届生，特别是以下两类困惑：

| 用户状态 | 典型困惑 |
| --- | --- |
| 方向不清 | 「我做过一些事，但不知道能用在哪些岗位」 |
| 方向已定但行动脱节 | 「知道想做什么，但不知道自己差在哪、下一步该做什么」 |

### 1.3 待解决的问题

1. **经历难以转化为能力证据**：学生能写出一段经历，却说不出这段经历对应哪些岗位要求的技能。
2. **方向判断与可执行实践脱节**：常规产品给出"适合什么岗位"的结论就结束了，不回答"接下来做什么"。
3. **职业建议缺少可追溯依据**：聊天式建议无法复核，学生无法判断建议从哪来。

### 1.4 产品形态与核心功能

职途是一个**可解释的职业技能匹配工具**，主流程由三个章节构成：

| 章节 | 做什么 | 用户得到的产出 |
| --- | --- | --- |
| **01 看见经历** | 写一段课程 / 社团 / 项目 / 实习经历，系统识别原话中的关键词并给出候选能力，由用户逐条确认并自评证据等级 | 一份自己确认过的技能画像 |
| **02 比较选择** | 从知识库中选出至多 3 个**不同方向**的候选，并列展示「已有起点」与「仍缺什么」 | 有依据的方向候选，而非单一排名 |
| **03 动手验证** | 先呈现一项含**交付物与验收标准**的行动；完成后记录作品位置、个人贡献与体验反馈 | 一件可展示的作品 + 一次复盘记录 |

辅助能力：

- **职业试驾**：不填经历也能做一项约 15 分钟的工作样本（数据分析 / 前端交互 / 产品分析三个样例），用于低成本试探方向。
- **岗位库与真实 JD 对照**：可粘贴一份真实 JD，经本地文本清洗与规则技能识别后返回命中别名证据，用户确认后可进入同一套差距检查。
- **简历导入**：支持 PDF / DOCX / TXT / MD（≤5MB），在应用服务端内存中提取纯文本用于技能预勾选，文件不落盘。
- **记录与导出**：规划与复盘可保存、回看，并导出为 Markdown。
- **数据后台**：岗位与技能数据可通过 `/admin` 进行 CRUD 维护（演示部署未开放，见「可复现信息」）。

> **Demo 形式**：产品已部署为公网可访问的网站，评审无需安装即可直接体验。入口与推荐体验路径见同包《产品 Demo 访问说明》。

## 二、设计思路

### 2.1 关键决策：不做「问 AI 我适合干什么」的聊天框

这是本项目最重要的一个设计取舍。

| | 被否决的方案 | 本项目方案 |
| --- | --- | --- |
| 输出形态 | 自然语言生成一段职业建议 | 结构化分数 + 可展开的分项构成 |
| 可解释性 | 黑盒，无法复核 | 公式公开，每个分数附 `reasons` 字符串数组 |
| 数据来源 | 模型生成 | 本地岗位 × 技能知识库 + 结构校验器 |
| 结果稳定性 | 依赖外部 API，同一输入可能不同输出 | 断网可运行，结果确定 |
| 交互重点 | 系统给答案 | 系统给候选，**用户确认** |

**决策理由**：职业建议的特殊性在于，用户需要据此做出真实决策。一段无法追溯来源的流畅文字，比一个能拆开看依据的数字更危险。

### 2.2 算法完全公开

```
技能覆盖  = Σ(用户确认技能的权重) / Σ(岗位必备技能权重)
证据覆盖  = Σ(用户确认且自评证据等级 ≥ 3 的技能权重) / Σ(岗位必备技能权重)
匹配分    = 技能覆盖 × 75% + 加分项覆盖率 × 15% + 方向契合 × 10%
方向契合  = 未勾选方向 → 1.0；勾选且命中 → 1.0；勾选但不命中 → 0.5
行动周期  = Σ(补技能与补作品行动的估算时长) / 每周投入时长（默认 10 小时/周）
行动顺序  = 核心权重降序，再按 权重 ÷ 估算耗时 降序
```

技能权重：`3` = 模板核心要求、`2` = 重要、`1` = 一般。

每个岗位的结果都带一组 `reasons` 字符串，直接说明这个分数是怎么来的：覆盖了几项、命中哪些核心要求、缺哪些关键项、加分项有没有、所选方向是否一致。

**证据覆盖与技能覆盖分开计算**，避免把"我自述会"等同于"我有材料证明我会"。

### 2.3 用户确认优先于自动判定

关键词识别只作为**候选提示**，是否算作自己的能力由用户决定。否定、学习中和经验有限等邻近表述不会自动预勾选，并会提示人工核对。

ASCII 技能别名按词边界匹配，避免 Java 命中 JavaScript、SQL 命中 NoSQL 这类嵌入误命中。

### 2.4 数据治理优先于覆盖面

- 岗位与技能为人工维护的本地模板，带 `_meta.version` 版本号。
- 修改数据后必须运行 `node scripts/data/validate-data.mjs` 回归，零错误才算通过。
- **拒绝用模型推断**技能稀缺度、薪资等无法复核的数字。

### 2.5 边界诚实写进产品

已知限制直接写在界面上，而不是藏在文档里：

- 不评估熟练度与项目质量，只看用户勾选与自评。
- 方向契合是粗粒度打分（命中 1.0 / 不命中 0.5），不是精细建模。
- 模板权重不等同于某家企业的实际初筛规则。
- 预估时长是经验估算，**不是精确值**。

## 三、设计过程

### 3.1 技术路线演进

```
[ V1：LLM 版 ]                    →    [ V2：确定性规则版 ]
  简历 + Prompt + 聊天                   简历 + 勾选 + 数字
  自由文本答案                           确定性算法（公式公开）
  不可解释                               匹配分可拆开看依据
  依赖外部 API                           断网也能跑
  存在生成错误风险                       移除模型生成错误；规则仍可能误识别
```

关键转折点：V1 阶段测试中发现模型**编造了不存在的课程链接与薪资数据**。评估后决定不再用 prompt 约束，而是整体转向本地知识库 + 确定性算法——这个"减法"决定了产品最终形态。

### 3.2 架构（四层，各层可独立验证）

```
data/                    知识库（人工维护 + 校验器）
   ↓
lib/db.ts                SQLite 数据层（Node 内置 node:sqlite，零数据库依赖）
   ↓
lib/matcher.ts           匹配 / 差距 / 路径算法（纯函数，前端拿到知识库后本地计算）
   ↓
app/api/*                REST API 层（全部返回纯数据）
   ↓
app/plan/page.tsx + components/   UI 层（15 个组件）
```

设计要点：**所有 API 只返回纯数据，匹配算法在前端浏览器内计算。** 这样服务端是纯 IO，算法在前端可单步调试，替换前端框架不需要改后端。

### 3.3 主流程重构

从最初的五步向导收敛为**三章节职业试选**。原因是：五步流程把"管理求职指标"放在了"解决方向困惑"之前，与用户真实问题错位。当前版本明确了"先解决方向不清，再谈长期计划"。

### 3.4 可靠性与边界加固

- 保存规划等待持久化结果，两种存储都不可用时**显示失败，不虚报成功**。
- 示例体验不会自动覆盖个人草稿，退出示例后恢复个人经历。
- 个人数据按 HttpOnly 签名访客会话隔离，服务端忽略客户端传入的用户 ID。
- 简历上传明确提示"文件会发送到当前应用服务端解析"，不做"永不上传"的笼统承诺。

## 四、商业价值与产品创新性说明

### 4.1 创新性

| 维度 | 同类常见做法 | 本项目做法 |
| --- | --- | --- |
| 结果形态 | 生成一段建议文字 | 结构化分数 + 可展开的分项构成 |
| 可解释性 | 黑盒 | 公式公开，每分附 `reasons` |
| 数据来源 | 模型生成 | 本地模板 + 结构校验器 |
| 输出稳定性 | 依赖外部 API | 断网可运行，结果确定 |
| 交互重点 | 系统给答案 | 系统给候选 + 要求用户确认 |
| 闭环完成度 | 止于"推荐岗位" | 延伸到**交付物 + 验收标准 + 复盘记录** |

**一句话差异化**：把"匹配"从黑盒打分变成可追溯、可反驳、可执行的行动清单。

### 4.2 商业价值

| 路径 | 说明 | 当前状态 |
| --- | --- | --- |
| B 端 · 高校就业中心 | 生涯教育课程配套工具、就业指导辅助系统 | 未接触客户 |
| C 端 · 学生个人 | 求职准备与方向探索工具 | 付费意愿未知 |
| 开源 + 影响力 | 开放知识库与算法，积累口碑 | 未开源 |

**诚实的商业边界**（必须写入）：

- B 端高校采购周期长、需招投标，短期难以转化。
- C 端学生群体付费意愿低，纯订阅模式存疑。
- **本项目目前没有收入，也没有已验证的用户规模数据。**
- 用户效果数据仍在收集中（计划见 `docs/USER-VALIDATION.md`），不宣称已提升就业或职业决策结果。

### 4.3 社会价值

项目直接回应"大学生就业指导资源不足"这一公共议题：将原本依赖个人经验的职业咨询过程，转化为**可自助完成、结论可复核**的工具流程。

## 五、AI Coding 工具使用情况

> 参赛通知要求：参赛作品须使用 AI Coding 工具完成，提交时须注明所使用的 AI 工具名称及其具体用途。
> 本节按「工具名称 + 具体用途」成对说明。

### 5.1 工具与用途

| AI 工具 | 具体用途 |
| --- | --- |
| TRAE | 梳理产品需求边界与信息架构；起草四层架构方案（知识库 / 算法 / API / UI）并对比取舍，用于早期技术选型 |
| WorkBuddy | 实现三章节主流程与 15 个前端组件；编写数据校验器与自动化验收脚本；整理项目文档与参赛材料 |
| Codex (OpenAI) | 辅助代码审查与边界问题定位（简历编码兜底、数据一致性、版本兼容），并协助重构主组件 |

> 三项工具均为「AI Coding 工具」，用途与 `docs/AI_LOG.md` 的四段式记录一一对应，可复核。

### 5.2 人机分工：AI 负责"造壳"，人工负责"装芯"

| 环节 | 主导方 | 说明 |
| --- | --- | --- |
| 架构方案对比与选型 | AI 主导，人类决策 | AI 列出多方案优缺点，人类拍板 |
| 模板代码 / CRUD / 配置文件 | AI 主导 | 样板代码生成 |
| Bug 定位 | AI 辅助 | 报错信息 + 上下文，快速定位 |
| 文档与说明书初稿 | AI 辅助 | 初稿生成后由人工逐句改写 |
| **岗位与技能数据内容** | **完全人工** | 数据错了算法就废，不交给模型 |
| **技能权重与时长估算** | **完全人工** | 直接影响算法输出 |
| **产品定位与边界** | **完全人工** | 「反幻觉」这一取舍来自产品判断 |
| **UI 文案** | **人工改写** | AI 生成的"AI 腔"是产品毒药，逐句改成人话 + 数字 |

### 5.3 关键决策：AI 建议被采纳与被否决

**AI 工具贡献最大的时刻，是它建议"应该不用 AI"。**

| 决策点 | AI 工具建议 | 人类决策 | 理由 |
| --- | --- | --- | --- |
| 数据存储 | JSON 做种子 + SQLite 做运行时 | 采纳 | JSON 可 diff 评审，SQLite 保证一致读 |
| 数据库依赖 | 用 Node 内置 `node:sqlite` 替代 better-sqlite3 | 采纳 | 实现零外部数据库依赖 |
| 简历解析 | 推荐 `unpdf` + `mammoth` 并处理编码兜底 | 采纳 | 本地解析，不调用模型 |
| 薪酬数据 | 用 prompt 约束模型输出薪资 | **否决** | 约束不能消除幻觉，改为只展示模板区间 |
| 稀缺度指标 | 用 LLM 推断技能稀缺度 | **否决** | 无法复核，改为人工标注 |
| 匹配主指标 | 把"方向契合"列为主指标 | **否决** | 方向是粗粒度，不应压过技能匹配，降为 10% 加分项 |

### 5.4 过程可核验性说明

赛制明确要求"AI 自动编程工具的使用流程须单独作为重点内容阐述，**不可简单内嵌于说明书**"。
因此本项目另附独立的过程记录（`docs/AI_LOG.md`），按「我提出的判断 → AI 的回复 → 我的决策 → 最终结果」四段式记录关键节点。

**诚实声明**：该日志为开发过程的**回顾性记录**，其中的代码归因比例未经严格统计，不作为量化结果。核心决策均有对应的代码可复核。

## 六、已知边界（坦诚写）

- **数据规模与来源有限**：579 岗 / 17 方向 / 134 技能为人工整理的本地参考模板，会随行业演化而局部过时；逐条招聘来源记录不完整，**不能当作真实市场统计**。
- **不核验项目质量**：证据覆盖依据用户自评等级，目前不检查作品附件或第三方证明。
- **规则识别可能误命中**：关键词识别基于规则启发式，不能替代上下文判断，人工确认环节不可省略。
- **无账号访客模式**：按浏览器会话隔离个人记录，不支持跨设备同步；数据库为单实例 SQLite。
- **方向契合是粗粒度打分**：命中 1.0 / 不命中 0.5，不是精细建模。
- **主流程没有大模型调用**：因此不会出现"AI 给出惊喜建议"；勾了什么就是什么，遇到库里没有的技能会被存为"自定义记录"且不参与评分，以避免假数据。
- **学习资源是平台搜索入口**：不是已经审核的指定课程。
- **预估时长不是精确值**：仅用于排序与节奏参考。
