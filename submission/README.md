# submission/ · 参赛提交材料工作区

本目录是「第二届新致杯人工智能创新大赛」提交材料的**唯一事实来源**。
打包脚本从这里读配置、收材料，产出可直接发送给主办方的 zip。

## 目录结构

```
submission/
  submission.config.json   提交元数据（项目名、队长、成员、AI 工具、材料选择）
  materials/               新致杯待提交的实体材料放这里
  edu-contest/             另一个比赛（AI+教育）的材料，不参与新致杯打包
  README.md                本文件
```

产出物写到仓库根的 `dist/submission/`，**该目录不进版本库**。

## 提交包结构

`npm run submit:build` 产出的 zip 根目录如下：

```
职途+队长.zip
  00-请先打开我.html          材料入口页（Demo 直达链接 + 体验路径 + 包内清单）
  01-提交信息.md              队长信息、Demo 地址、AI 工具名称及用途
  doc-职途产品说明书.pdf       参赛材料（说明书 / 商业计划书 二选一）
  demo-产品Demo访问说明.pdf    Demo 访问说明
  源码/                       完整产品源码，可离线复现
```

前两项与 `源码/` 由脚本自动生成/收集，`materials/` 只需放 `doc-` 与 `demo-` 两类实体材料。

> **为什么要放源码**：Demo 是在线网站，链接一旦失效，包内就只剩文档。
> 源码是唯一的离线凭证，同时支撑通知要求的「AI Coding 工具使用情况」披露。
> 打包脚本会自动排除 `node_modules/`、`.next/`、`dist/`、`career.db*`、日志与 2MB 以上单文件。

## 三步走

1. 填 `submission.config.json`（队长姓名、电话、成员、AI 工具用途必填）。
2. 把材料按命名约定放进 `materials/`（见下）。
3. 运行 `npm run submit:build`，拿到 `dist/submission/<项目名称>+<队长姓名>.zip`。

## materials/ 命名约定

脚本按**文件名前缀**归类，前缀不区分大小写：

| 前缀 | 归类 | 数量 | 说明 |
| --- | --- | --- | --- |
| `doc-` | 产品说明书 / 商业计划书 | 恰好 1 份 | 具体是哪一种由 `materials.docType` 决定 |
| `demo-` | 产品 Demo | 至少 1 个 | 视频、网站导出物、可运行包均可 |

示例：

```
materials/
  doc-职途产品说明书.md
  demo-产品Demo访问说明.md
```

前缀缺失时脚本会退回按扩展名推断，并给出警告；仍无法归类则报错。

> 本项目的 Demo 采用**网站形式**：产品已部署到公网，`materials/` 中放一份《产品 Demo 访问说明》
> 列明入口与体验路径；可访问地址同时写在 `submission.config.json` 的 `materials.demoUrl`。

## 材料要求（来自参赛通知，非本项目自定）

说明书或商业计划书**二选一**，内容须包含：

1. 产品介绍
2. 设计思路
3. 设计过程
4. 商业价值与/或产品创新性说明
5. AI Coding 工具使用情况

Demo 形式为「视频、网站或其他形式均可」。

提纲模板见 `submission/templates/`。

## 边界声明

- 通知**未规定**文件类型、大小上限、页数字数。脚本中的 25MB 是工程建议值（主流邮箱单附件上限），不是主办方约束。
- 提交动作本身仍通过邮箱完成，本项目不代发邮件，只负责把包打对、把材料查全。
