## 一、产品介绍

（对应通知必备项 ①）

1. **目标用户**：大学生 / 应届生，尤其是方向不清、经历难以转化为能力证据的群体。
2. **核心问题**：职业建议缺少可追溯依据；方向判断与可执行实践脱节。
3. **产品形态**：可解释的职业技能匹配工具，三章节主流程 + 岗位知识库 + 记录与导出。
4. **当前状态**：本地可运行 Demo，主流程与 API 测试通过，**尚未公开部署**。

---

## 二、设计思路

（对应通知必备项 ②）

1. **技术路线选择**：主流程不调用生成式模型，改用本地知识库 + 确定性算法。
   - 理由：可解释、可复核、结果稳定、断网可运行。
   - 代价：不具备"生成惊喜建议"的能力，需要用户主动确认输入。
2. **可解释算法**：匹配分 = 覆盖率 × 75% + 加分项 × 15% + 方向契合 × 10%，公式公开。
3. **用户确认机制**：识别结果只作候选，能力与证据等级由用户确认。
4. **数据治理**：模板数据带版本号与结构校验器，改数据必须跑回归。

## 四、市场与用户

> 本节所有市场数据必须标明来源；无来源的数字不要写。

1. **目标市场**：高校生涯教育与就业指导。
2. **用户画像**：低年级（方向探索）与高年级（求职准备）两类，需求不同。
3. **需求验证状态**：**尚未完成用户访谈**。计划见 `docs/USER-VALIDATION.md`。
   - 首轮计划邀请 5–8 名在校学生 + 2 名从业者
   - 观察指标：任务完成率、需要提示的步骤、重复出现的误解、能否说出下一步
4. **规模估算**：待补。不要用未标注来源的宏观数字充数。

## 五、竞争与差异化

（与必备项 ④ 的创新性说明合并撰写）

| 竞品类型 | 代表形态 | 本项目差异 |
| --- | --- | --- |
| 测评问卷 | 霍兰德类兴趣测评 | 不测兴趣，比对岗位技能要求与证据缺口 |
| 聊天式咨询 | LLM 职业顾问 | 不给自由文本建议，给可拆解的分数与依据 |
| 招聘平台 | 岗位检索与投递 | 不做投递，做"能否胜任"的差距与补齐路径 |
| 简历工具 | 模板与润色 | 不美化措辞，识别能力线索并要求用户确认 |

**差异化一句话**：把"匹配"从黑盒打分变成可追溯、可反驳、可执行的行动清单。

## 六、商业价值与创新性

（对应通知必备项 ④）

### 6.1 创新性

- 反幻觉设计：主流程零模型调用，所有数字可追溯
- 可解释算法：每个分数附 `reasons` 字符串数组
- 行动闭环：差距 → 交付物 → 验收标准 → 复盘记录

### 6.2 商业化路径（均为假设，需验证）

| 路径 | 说明 | 当前状态 |
| --- | --- | --- |
| B 端 · 高校就业中心 | 生涯课程配套工具 / 就业指导辅助 | 未接触客户 |
| C 端 · 学生个人 | 求职准备工具 | 付费意愿未知 |
| 开源 + 影响力 | 开放知识库与算法，积累口碑 | 未开源 |

> **诚实边界**：B 端采购周期长、需招投标；C 端学生付费意愿低。
> 这两点必须写进计划书，否则会被评审直接问倒。
