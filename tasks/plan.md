# 职途 career-navigator 分阶段优化计划

> 更新于 2026-09-21。本文档已与仓库实际代码逐项核对，不再是「计划态」，而是「实际态 + 下一步」。

## Overview

原目标：先把「真实 JD → 技能识别 → 差距计算 → 学习路径 → 持久化」的产品闭环修完整，
再引入可解释的 AI 技能识别，最后基于用户行为做个性化推荐。第一阶段以***REMOVED***和求职演示的可验证性为优先，不强行接入 LLM。

**Phase 1 已全部完成**（见下）。Phase 2 / Phase 3 未启动，且 Phase 2 的前提需要重新评估。

## 与原计划的偏差（重要）

1. **产品形态改了**。原计划的「五步向导」已被替换为三章节「职业试选」：
   写经历 → 核对候选能力 → 比较少量不同方向 → 检查证据缺口 → 先做一件具体作品。
   原因：上一轮的工作台、侧栏、指标首页服务的是「管理求职指标」，而目标学生的真实卡点是「方向不清」。
   当前首页 / 方向页 / 行动页见 `components/ExperienceInput.tsx`、`SkillTranslation.tsx`、`CareerChoices.tsx`、`GapView.tsx`、`PathView.tsx`。
2. **主组件换了位置**。主组件现在是 `app/plan/page.tsx`（约 809 行，组件名仍为 `Home`）。
   原 `app/page.tsx` 被删除后根路径曾返回 404；2026-09-21 已补回一个只做 `redirect("/plan")` 的 `app/page.tsx`，
   实测 `/` → 307 → `/plan` 200。
3. **知识库观察独立成页**。`/market` + `components/MarketBoard.tsx`，复用 `/api/knowledge`，纯 SVG/CSS，零图表库。
4. **「我的 JD」入库**。`/api/jds`（CRUD）+ `/api/jds/parse`（识别），真实 JD 可收藏并与画像比差距。
5. **Phase 2 前提待重新评估**。当前产品叙事明确写着「没有真实大模型调用，AI 辅助开发不等于 AI 产品能力」。
   若赛道规则要求产品必须使用大模型，需要按官方规则单独接入并做规则 / 模型对照评测，不能顺手接一个模型就宣称 AI 能力。
